19. Difference between WHERE and HAVING.

| **WHERE**                                                    | **HAVING**                        |
| ------------------------------------------------------------ | --------------------------------- |
| Filters rows **before** grouping                             | Filters groups **after** grouping |
| Cannot use aggregate functions (`SUM`, `COUNT`, `AVG`, etc.) | Can use aggregate functions       |
| Used with `SELECT`, `UPDATE`, and `DELETE` statements        | Used mainly with `GROUP BY`       |
| Applied before `GROUP BY`                                    | Applied after `GROUP BY`          |

21. Can WHERE be used with aggregate functions?

53. What is a View?

VIEW 

View: A virtual table. No data is stored. Always shows the latest data but may be slower for complex queries.

Table --> Data Stored

54. Advantages of Views.

Views provide security, simplify complex queries, improve reusability,
provide data abstraction, maintain consistency, and help users access data without directly exposing underlying tables


55. Can we update a View?

56. Difference between View and Table.
	Table:
Stores actual data.
Permanent database object.
Occupies storage.
Main source of data.
		View:
Stores a SQL query, not usually the data.
Provides security by hiding columns/rows.
Simplifies complex queries.
Acts like a virtual table.

57. What is an Indexed View (Materialized view)?

An indexed view is a view with a physical index created on it. Unlike a normal view, which stores only the query definition, an indexed view stores the computed result physically, improving performance for complex queries such as aggregations and joins. However, it requires extra storage and can slow down insert, update, and delete operations because the indexed view must also be maintained.

72. What is Index Fragmentation?
	Index Fragmentation is the condition where an index becomes disorganized due to frequent INSERT, UPDATE, and DELETE operations, causing slower query performance because the database has to read more pages to find data.

TEMPORARY OBJECTS

91. Difference between Temporary Tables and Table Variables.
	Temporary tables are temporary database tables used for storing intermediate results and are suitable for large data operations. 
	Table variables are temporary variables used to store small amounts of data within a limited scope

92. What is a Global Temporary Table?
A Global Temporary Table is a temporary table created with ## that can be accessed by multiple sessions and remains available until the last session using it is closed.

93. When would you use a Temp Table?
	when you need to store intermediate results temporarily during a query, stored procedure, or complex data processing.
